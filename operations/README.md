# Qinghe · Market Operations

A working internal tool for recording market-day sales and inventory, turning existing spreadsheets into a dashboard, and testing a cross-subsidy scenario. English is the default; the interface also supports Chinese. It is separate from the legacy customer-preorder application in the repository root.

## Start

Requires Node.js 24 or newer. Run inside this directory:

```sh
npm ci
npm run dev
```

Open **http://127.0.0.1:5186**. The API listens on **127.0.0.1:3016**. For a built local application:

```sh
npm run build
npm start
```

Then open **http://127.0.0.1:3016**. The server binds to this computer only. Shared team hosting needs an authenticated deployment; this version is a complete local tool and does not implement multi-user accounts.

## Use

1. Explore **Example** to see synthetic figures. This workspace is stored in browser local storage.
2. Choose **My records** for the actual workspace. It starts empty and is stored in `data/operations.sqlite`, outside Git. The two workspaces do not merge. JSON and Excel exports generated by the example workspace are rejected when imported into actual records.
3. **Log market day** records a date, stop, session, actual tender amounts, transaction count, costs and source. Dates refer to the market's New York business date. Use one consistent seller/accounting boundary within a workspace.
4. **Inventory** records opening, received, sold, donated, spoiled, transferred out and closing quantities. Each product and unit stays separate. Stock must balance before saving.
5. **Import & export** accepts `.xlsx`, `.csv` and the app's JSON backups. Choose a sheet and record type, map column names, validate and review, then confirm. Import Market days and Inventory sheets separately. Existing identical records skip; conflicting records stop the whole batch. Edits happen through the register, not by silently overwriting an import.
6. Export the Excel workbook for the complete current workspace, with a Read me sheet, or JSON for a complete record backup. Exports include all records regardless of dashboard filters. Restore missing records by importing a JSON backup; this is append/merge, not a destructive database replacement.
7. **Scenario lab** shows an editable, explicitly hypothetical contribution calculation. It does not alter prices or estimate demand elasticity.

The manager's final tracking sheet has not yet been supplied. Column mapping and the empty template provide a usable interim interface. Do not assert that the client's exact spreadsheet has already been integrated.

## Definitions

| Measure              | Definition                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------- |
| Sales                | Cash + credit/debit + SNAP/EBT + Market Bucks + WIC/FMNP + other mutually exclusive recorded net tender amounts |
| Average per day      | Sales divided by distinct held market dates, aggregating multiple stops on one date                             |
| Best sales day       | Highest total recorded sales across all held sessions on one date                                               |
| Assistance share     | (SNAP + Market Bucks + WIC) / total sales; undefined when sales are zero                                        |
| Session contribution | Sales minus all four recorded cost categories, available only when all four are known                           |
| Produce cost         | Goods consumed including losses; not all procurement cash outlays, and not losses counted twice                 |
| Stock balance        | Opening + received = sold + donated + spoiled + transferred out + closing                                       |

Amounts are stored as nonnegative integer US cents and exported as USD decimals. Refund-adjusted net tender amounts must remain nonnegative in this first version. Separate refund events, negative net settlement periods, grant accounting and bank reconciliation belong in a detailed ledger. Unknown transaction counts and costs remain blank, distinct from zero. An imported missing payment column requires explicit confirmation that this tender was unused.

Revenue charts omit missing dates; they do not treat missing records as zero. Weeks start Monday. Data are descriptive, not estimates of causal effects, future demand or financial sustainability. Vendor gross sales do not automatically equal operator revenue. Payment assistance is already in sales and must not be counted again as grant income.

## Persistence and validation

The local SQLite database stores actual records and a revision counter. Every write is transactional; stale browser tabs get a conflict instead of overwriting newer records. Import conflicts roll back the entire batch. A small audit table records write time, action and revision; it is not a complete accounting audit trail or a replacement for backups. Export backups regularly to the organization's private storage.

`OPERATIONS_DATABASE` changes the database path. `PORT` changes the API/static server port; the development proxy uses port 3016. No original operating databases or existing application files are used for this tool.

## Checks

```sh
npm run check
npx playwright install chromium
npm run test:ui
```

The unit/integration tests cover exact currency parsing, calendar dates, cancellation, balanced fractional stock, daily aggregation, unknown costs, weekly boundaries, contribution arithmetic, persistent saves, stale writes, cross-origin writes and atomic duplicate/conflicting imports. Browser checks cover language, filters, mobile overflow, actual CRUD, refresh persistence, Excel round-trip, example-data isolation, CSV import and scenario changes. Tests use a temporary operating database.

To use an existing compatible Chromium executable, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. ExcelJS loads only on spreadsheet import/export; its larger parser bundle is not part of the initial dashboard download. The UI has no remote font or service dependencies after building.

## Source layout

`src/main.tsx` contains the five work areas, `src/data.ts` handles spreadsheet conversion, `shared/domain.ts` defines validation and calculations, and `server/` supplies local persistence. The root application remains a historical/specialized customer-and-vendor implementation. Pre-internal-tool source snapshots are preserved in the private legacy repository under `archive/pre-internal-2026-11-16/production` and `archive/pre-internal-2026-11-16/working-copy`.
