# Qinghe · Market Operations

A working internal tool for recording market-day sales and inventory, turning existing spreadsheets into a dashboard, comparing supplier delivered costs, and testing procurement and cross-subsidy scenarios. English is the default; the interface also supports Chinese. It is separate from the legacy customer-preorder application in the repository root.

## Public website

Open **https://lucasyanzy.github.io/qinghe-market-guide/**. GitHub Pages serves the dashboard at the original project URL, with no local service required.

The public build keeps actual records in this browser only, under a separate storage key from synthetic examples. It never uploads record contents. Use Excel/JSON exports to back up or move records to another browser or device. Clearing site data removes browser records. There is no shared online database or automatic synchronization across users/devices.

Writes use Web Locks and a revision check to prevent stale tabs from overwriting newer records. Unsupported browsers can explore examples and read saved data, but should use a current browser to save records. Corrupt or full storage produces an error and leaves prior data intact.

```sh
npm run build:public
npm run test:public
```

The Pages workflow builds `operations/dist-public` with the `/qinghe-market-guide/` asset prefix and publishes it as the original website's homepage. Local and public builds use separate output directories. Real operating databases, browser records and exports are excluded from the build.

## Start the local database version

Requires Node.js 24 or newer. Run inside this directory:

```sh
npm ci
npm run dev
```

Open **http://127.0.0.1:5186**. The API listens on **127.0.0.1:3016**. For a built local application:

```sh
npm run build
npm start
```

Then open **http://127.0.0.1:3016**. The server binds to this computer only. This local database version does not implement multi-user accounts. The public browser version described above runs separately.

## Use

1. Explore **Example** to see synthetic figures. This workspace is stored in browser local storage.
2. Choose **My records** for the actual workspace. It starts empty. The public version saves it in browser storage; the local server version saves it in `data/operations.sqlite`, outside Git. The two workspaces do not merge. JSON, Excel, CSV and TSV exports generated by the example workspace are rejected when imported into actual records.
3. **Log market day** records a date, stop, session, actual tender amounts, transaction count, costs and source. Dates refer to the market's New York business date. Use one consistent seller/accounting boundary within a workspace.
4. **Inventory** records opening, received, sold, donated, spoiled, transferred out and closing quantities. Each product and unit stays separate. Stock must balance before saving.
5. **Import & export** accepts `.xlsx`, `.csv`, `.tsv` and the app's JSON record backups (8 MB maximum). Validate all recognized record sheets together, or map one sheet manually. English and Chinese column aliases are supported. Errors are collected by row and can be downloaded as CSV. Nothing is saved until a valid preview is confirmed. Identical records skip; conflicting records reject the entire batch. Customers are never silently treated as transaction counts.
6. Export the complete Excel workbook (summary, daily/monthly sales, market performance, raw sessions, inventory, supplier quotes and definitions), JSON record backup, or individual CSV/TSV tables. Register search, status, sort and pagination help review larger datasets. Filtered CSV/Excel exports include **all matching rows**, not just the visible page. JSON restores missing records by merging; it does not overwrite conflicts. Spreadsheet exports preserve blank unknown costs and transaction counts.
7. **Procurement** saves supplier quotes by date, product, unit and specification. Compare only equivalent products. Pack size is raw units per pack; price and handling are per pack, delivery per order, and minimum order is the goods subtotal before fees. Usable yield adjusts stock. The model rounds up whole packs and respects order minimums. Low/base/high demand, excess stock, unmet demand, delivered unit cost, break-even price and contribution update together. The sensitivity chart recomputes orders at each target while holding base demand fixed. Quotes are offers, not purchases; no real demand forecast is inferred.
8. Procurement inputs can be remembered in the current browser separately for each workspace. Save/restore a scenario JSON file to carry its inputs and exact quote; restore the matching quote from a records backup first. Export scenario results with their source and assumptions as CSV. These assumptions stay separate from operating records and do not write sales or stock.
9. **Scenario lab** tests cross-subsidy contributions and funding requirements, including a loss sensitivity chart and calculation export. It does not alter prices or estimate demand elasticity.

The manager's final tracking sheet has not yet been supplied. Column mapping and the empty template provide a usable interim interface. Do not assert that the client's exact spreadsheet has already been integrated.

## Definitions

| Measure              | Definition                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------- |
| Sales                | Cash + credit/debit + SNAP/EBT + Market Bucks + WIC/FMNP + other mutually exclusive recorded net tender amounts |
| Average per day      | Sales divided by distinct held market dates, aggregating multiple stops on one date                             |
| Best sales day       | Highest total recorded sales across all held sessions on one date                                               |
| Assistance share     | (SNAP + Market Bucks + WIC) / total sales; undefined when sales are zero                                        |
| Session contribution | Sales minus all four recorded cost categories, available only when all four are known                           |
| Produce cost         | Goods consumed including losses; not all procurement cash outlays, and not losses counted twice                 |
| Stock balance        | Opening + received = sold + donated + spoiled + transferred out + closing                                       |

Amounts are stored as nonnegative integer US cents and exported as USD decimals. Refund-adjusted net tender amounts must remain nonnegative in this first version. Separate refund events, negative net settlement periods, grant accounting and bank reconciliation belong in a detailed ledger. Unknown transaction counts and costs remain blank, distinct from zero. An imported missing payment column requires explicit confirmation that this tender was unused.

Market-performance charts use the complete-cost held-session cohort for **both sales and costs**. Missing costs remain unavailable. Average basket uses only sessions with known transaction counts in both its numerator and denominator. Cancelled sessions and their known costs are reported separately in Excel; cohort contribution is not an organization-wide profit figure. Inventory charts show one product/unit/session at a time; cumulative outbound tables never sum opening/closing stock across dates or combine units.

Revenue charts omit missing dates; they do not treat missing records as zero. Weeks start Monday. Data are descriptive, not estimates of causal effects, future demand or financial sustainability. Vendor gross sales do not automatically equal operator revenue. Payment assistance is already in sales and must not be counted again as grant income.

## Persistence and validation

The local SQLite database stores actual records and a revision counter. Every write is transactional; stale browser tabs get a conflict instead of overwriting newer records. Import conflicts roll back the entire batch. A small audit table records write time, action and revision; it is not a complete accounting audit trail or a replacement for backups. Export backups regularly to the organization's private storage.

`OPERATIONS_DATABASE` changes the database path. `PORT` changes the API/static server port; the development proxy uses port 3016. No original operating databases or existing application files are used for this tool.

## Checks

```sh
npm run check
npx playwright install chromium
npm run test:ui
npm run test:public
```

The additional toolkit tests verify migration of legacy records without data loss, quote persistence and atomic conflicts, multi-sheet Excel roundtrips, formatting-only trailing columns, multiline CSV/TSV, formula-safe exports, full row-error collection, minimum-order arithmetic, missing-data cohorts, JSON restore, pagination/filter exports, procurement CRUD, scenario restore, and mobile charts. The unit/integration tests cover exact currency parsing, calendar dates, cancellation, balanced fractional stock, daily aggregation, unknown costs, weekly boundaries, contribution arithmetic, persistent saves, stale writes, cross-origin writes and atomic duplicate/conflicting imports. Browser checks cover language, filters, mobile overflow, actual CRUD, refresh persistence, Excel round-trip, example-data isolation, CSV import and scenario changes. Public build checks additionally cover the published asset prefix, no API dependencies, persistence across reloads, conflicting browser tabs, isolated visitor records and spreadsheet/backup downloads. Tests use a temporary operating database.

To use an existing compatible Chromium executable, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. ExcelJS loads only on spreadsheet import/export; its larger parser bundle is not part of the initial dashboard download. The UI has no remote font or service dependencies after building.

## Source layout

`src/main.tsx` contains the application and core registers; `src/Exchange.tsx`, `src/Insights.tsx` and `src/Procurement.tsx` implement spreadsheet workflows, operational visuals and purchasing. `src/data.ts` handles spreadsheet conversion; `shared/domain.ts` and `shared/analytics.ts` define validation and calculations; and `server/` supplies local persistence. The root application remains a historical/specialized customer-and-vendor implementation. Pre-internal-tool source snapshots are preserved in the private legacy repository under `archive/pre-internal-2026-11-16/production` and `archive/pre-internal-2026-11-16/working-copy`.
