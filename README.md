# 青禾 · Rutgers 社区农夫市集

独立的社区市集项目，包含公开市场导览与顾客、商户、学校三端完整应用。非 Rutgers 官方网站。

- **公开只读 Demo 与导览站**：[市场时间、导航与资源](https://lucasyanzy.github.io/qinghe-market-guide/)。公开站采用 GitHub Pages，提供[顾客、商户、学校三端 Demo](https://lucasyanzy.github.io/qinghe-market-guide/demo/)、日历、地址导航、历史价格档案和帮助。Demo 使用合成示例，可切换身份、筛选和浏览；不开放真实登录、预购、付款或后台写入。完整应用仅供独立本地运行。
- **架构说明**：[docs/architecture.md](docs/architecture.md)。公开站与完整应用使用独立入口，共享日程、组件和翻译；价格分析与学校模块按需加载。
- **部署手册**：[docs/deployment.md](docs/deployment.md)。包含 Node 24、Docker / Railway、持久化卷、反向代理、备份恢复及回滚流程。

```sh
npm ci
npm run dev           # 完整应用：前端 5173 / API 3001
npm run check         # 双入口构建 + API、日历、权限与部署回归
npm run test:public   # 公开站导航、路径、语言、手机布局
npm run test:ui       # 完整应用浏览器回归
```

`npm run build:public` 生成独立的 `dist-public/`，无需 API；`npm run build` 生成完整应用的 `dist/`，与 Express API 同源运行。`.github/workflows/` 提供检查、容器启动验证和公开站构建产物。网站文件发布到独立的 `LucasYanzy/qinghe-market-guide` 仓库，原源码仓库继续保持私有。运行配置由 `server/config.mjs` 统一校验；生产环境必须显式指定持久化 `DATABASE_PATH`，默认关闭演示模式并启用安全 Cookie。本地 `npm run dev` 与 `npm start` 自动加载 `.env`，不要提交环境文件、运营数据库或备份。

---

一个可运行的全栈雏形，包含顾客端（Client）、商户端（Retailer / Vendor）和学校管理方（University Admin）。学校管理方在市场及商户之上统一配置运营市场、查看全盘统计与社区参与情况，也可以通过服务台替不会使用软件的商户完成日常操作。当前使用演示市场、示例蔬菜和生成的历史价格，不代表 Rutgers 官方的商品、报价或营业安排。

## 本轮范围

- 顾客端：当日蔬菜、搜索与分类、购物袋、预购自提、订单状态与待确认订单取消。
- 首页与市场页：2026 开市日历、最近场次、日期与地址搜索、营业季和休市规则、驾车/步行/公交导航、地址复制、日历下载。
- 帮助中心：Market Bucks、Food Pantry 等官方资源入口、联系方式、预购和商户使用 FAQ。
- 商户端：经营概览、商品上架与编辑、价格和库存调整、确认预购与自提。
- 学校管理方：全盘概览、7 / 30 / 90 天及全部时间统计、市场新增与编辑、市场启停与预购开关、跨商户经营数据、社区参与和规划服务范围。
- 价格观察：历史记录、7 天线性趋势预测及误差说明。
- 基础邮箱登录、顾客注册、服务端角色校验，SQLite 持久化。

预购采用**到场付款**，尚未接入线上支付、短信、真实农场数据或生产运营系统。当前适合本地评审与迭代，不是生产上线版本。

页面支持直接访问、刷新、浏览器前进后退及新标签页打开。当前标签页通过 sessionStorage 保留当天的购物袋、自提日期、时段和备注，刷新后恢复，重新读取最新价格与库存；关闭标签页、退出或切换账号、跨日后不恢复旧选择。登录恢复后仍需明确确认下单。商户页需要商户账号，直接访问会先显示登录入口；服务端继续校验所有商户操作权限。未知网址显示返回首页入口。

顾客导航统一为「市场与导航、逛逛市集、我的预购」三项：桌面横向显示，手机固定在底部，顾客端不再使用侧栏和折叠菜单。顶部只保留帮助、语言和统一登录；价格观察、关于项目、商户与学校登录移到精简页脚。商户和学校登录后保留各自的管理导航。

首页优先显示最近开市时间、地点和导航，移除重复宣传与说明区块。商品分类和搜索直接可用，排序与库存选项收进「筛选与排序」，已选条件可一键清除。帮助页先显示四个常见问题，一次展开一项；Market Bucks、SNAP/EBT 与食品资源按需展开，官方联系方式直接可见。以上交互支持键盘及中英文切换。

商品卡片直接增减数量；选好商品后，固定购物袋入口显示已选数量及预估金额，手机端位于底部导航上方。筛选面板可通过点外部或 Escape 关闭。购物袋显示市场、农场和自提日期，时段加载失败可保留输入并原地重试；空购物袋可直接返回商品区域。

### 中英文界面

页眉中的「中文 / EN」切换顾客端与商户端的界面语言，浏览器会保存选择，并同步其他已打开的同站点标签页。导航、页面标题与描述、市场及食品援助说明、价格档案、商品详情、表单、订单状态和错误提示均支持切换。商品、库存和市场搜索同时匹配中英文，不会因切换语言而清空购物袋或正在填写的内容。

中文文案是稳定翻译键，英文词典位于 `src/translations/en.ts`；原始英文标签的中文显示位于 `src/translations/zh.ts`。新增界面文案使用 `t()`，含数量或名称的句子使用完整模板与参数，避免拆句拼接。需要随语言切换重新显示的通知和错误使用 `{ message, values }`，其中 `{ message: "藤熟番茄" }` 形式的参数会翻译，普通字符串参数保留原文。

姓名、订单备注和未知的自定义商品内容保持原样。英文编辑器显示已收录示例商品的英文名称与描述；未编辑时保存不会改写原始数据。历史采价商品在英文模式只显示英文名称，中文模式保留双语名称；地址、价格、原始单位的不确定性和优惠条件不因切换语言而改变。

`npm test` 会检查现有界面、演示商品、参考资料及 API 消息的词典覆盖和参数一致性；浏览器测试还检查所有页面、预购及商户编辑流程、语言保存和 320/390px 手机布局。浏览器测试自动分配独立本机端口。

## 交互与动画

沿用青禾的浅绿与米白视觉，保留滚动内容出现、筛选与排序时的商品位置过渡，以及弹窗开合和按钮反馈。首页优先显示开市日历与到场信息。动画使用原生 CSS 与 Web Animations API，没有新增依赖；系统开启“减少动态效果”时关闭这些效果，内容始终可读。

- 商品卡片支持增减数量，与购物袋同步；加购时绿色「+1」小圆从按钮起跳，沿弧线进入当前可见的购物袋，再由袋口弹动和「+1」提示完成接收反馈。详情页也有独立购物袋入口。
- 已选商品保留淡绿状态，数量与金额更新有轻量反馈。飞行只动画 `transform` 和 `opacity`，不复制商品图片；同时最多 3 个圆点，超出时仍立即更新数量。滚动、切页、缩放窗口或切到后台时清理效果，缺少动画 API 时保留正常操作。
- 搜索、分类、库存与排序条件以可撤销标签展示，支持一键重置。
- 向下浏览后显示购物袋快捷入口（已选数量、预估金额）与返回顶部按钮；购物袋继续保留本次会话的自提草稿。
- 商户与学校的手机菜单支持关闭按钮、Esc、Tab 焦点约束、背景滚动锁定，并在切回桌面宽度时自动关闭；访客使用三个固定主入口。

新增浏览器回归覆盖数量同步、组合筛选、购物袋草稿、手机菜单、英文反馈、减少动态效果、飞行落点和动画清理，并用 4 倍 CPU 减速模拟检查连续加购。

## 本地启动

需要 **Node.js 24+**（使用内置 `node:sqlite`）。

```bash
cd Rutgers-Community-Farmers-Market
npm ci
npm run dev
```

前端端口 `5173`，API 端口 `3001`。Vite 将 `/api` 请求代理给后端，不需要额外配置 CORS。

首次启动自动创建 `data/market.sqlite`，初始化当天演示商品与最近 28 天的示例历史价格。页面中的演示入口可以登录三种角色：

| 角色 | 邮箱                   | 演示密码          |
| ---- | ---------------------- | ----------------- |
| 顾客 | `client@qinghe.demo`   | `MarketDemo2026!` |
| 商户 | `retailer@qinghe.demo` | `MarketDemo2026!` |
| 学校管理方 | `admin@qinghe.demo` | `MarketDemo2026!` |

演示密码是公开的测试凭据，请勿用于真实账号。示例数据库及环境文件已加入 `.gitignore`。

学校管理入口位于桌面顶部和页脚，商户也可通过切换账号进入学校演示。学校管理页面支持直接访问与刷新，但只有 `admin` 角色可以读取管理 API 或保存市场设置；顾客注册不能创建管理账号。演示模式升级旧数据库时保留既有账号、会话、市场、商品与订单，并补充学校演示账号；`DEMO_MODE=false` 不会自动创建管理员；使用下方的 `npm run setup:admin` 在独立运营数据库建立首位管理员。

运营市场设置与官网市场目录分别管理。关闭市场或暂停预购后，该市场的商品不再出现在可预购列表中，服务端也会拒绝旧购物袋的新订单；已有订单仍可由商户履约。市场名称、地址、营业说明、经纬度、服务社区和规划半径（0.1–100 km）均持久化。官网目录的来源及核对日期不受这些设置影响。

全盘统计按美国东部时间的**自提日期**筛选。已完成交易额只包含 `completed` 订单；待履约金额包含 `pending` / `confirmed`；预购总数包含取消订单，完成率以全部订单为分母。参与顾客以已完成订单去重，全盘和各市场分别计算；跨市场人数不可简单相加。商户交易额使用订单商品价格快照，避免多商品订单重复计数。社区圆圈按市场坐标和设置半径绘制，表示规划范围，不代表实际覆盖人口或顾客住址；没有食品援助核销、减碳或住址数据时不生成相应影响数字。

### 多市场与社区可视化

学校管理方可在 `市场设置` 中新增市场、分配已有商户、批量开放或暂停预购。同一商户可经营多个市场，商品上架时明确选择市场；退出某市场会下架该市场商品，保留历史订单与履约权限。重新入驻不会自动重新上架。存在待履约订单的商品不能直接迁移到其他市场。

学校全局市场选择器支持独立统计和 `?market=id` 分享/刷新。社区页面的 2.5D 示意图支持市场节点选择、服务范围图层、俯视切换、缩放/复位与管理入口。图形按配置的经纬度和半径投影；只显示规划范围，不计算实际覆盖人口。

四市场预览数据可单独生成：`node scripts/seed-school-preview.mjs`，写入 `data/school-admin-preview.sqlite`。使用 `DATABASE_PATH=./data/school-admin-preview.sqlite PORT=3199 npm start` 查看。附加市场和坐标明确标记为演示，不生成参与人数或订单。

### SNAP / EBT 现场购买

学校在每个市场的 **SNAP / EBT** 标签页分别维护市场接受状态、服务台代币/商户终端模式、核实日期、公开依据与现场指引，再确认各入驻商户。初始状态均为未确认，不自动宣称 Rutgers 接受 EBT。商户上架时按 USDA 规则标记商品食品资格，未核实项不计入 SNAP 食品预估。

购物袋通过服务端生成逐项资格和金额拆分。只有市场、商户和至少一项食品均满足条件，才可提交现场 SNAP/EBT 付款意向；不合资格和未核实商品需要其他付款方式。服务端在提交时重新检查政策、价格和库存，失败不预留库存。订单保存资格、价格、核实日期与现场指引快照，顾客和商户均可查看。社区页统计接受准备情况和非取消的付款意向订单。

当前不处理在线 EBT，不收集卡号、PIN 或福利余额，也不发放/核销代币。最终付款、余额不足时的补差及退款由现场合规流程处理。预购或完成自提不证明实际 SNAP 核销；Market Bucks 与 SNAP 是独立项目。USDA/NJ 官方规则及实现边界见 [`references/snap-ebt-sources.md`](references/snap-ebt-sources.md)，核对日期 **2026-10-29**。

### 商户不操作软件的现场流程

学校登录后进入 `/admin/operations`，按市场和工作日期处理。商户只需向工作人员报供货量并照纸质清单备货，不要求注册、手机或扫码。

1. **营业前**：在市场设置新增/核对市场；在「代办商户与商品」登记商户、可选的联系人/电话，代录指定日期、价格、单位和可预购数量。联系方式仅供管理员现场联络，不自动发送短信。
2. **开放预购**：在「开市与接单」建立日期、起止时间、当日接单截止、时段长度与每时段订单容量。保存草稿后明确点击开放。场次按美国东部时间计算，关闭接单不妨碍已有订单交付。
3. **备货交接**：在「订单与交付」先与商户核对供货，再逐单确认。按市场/商户打印大字备货单；清单包含商品数量、时段、状态、顾客备注及核对人签名处，不包含取货码，也不证明已经收款。
4. **到场领取**：工作人员输入顾客订单中的六位取货码；现场实际付款完成后，明确填写现金/银行卡/SNAP 金额及小票参考号，合计必须等于订单金额。SNAP 不能超过订单保存的合资格食品额，需要已有付款意向与小票参考号。系统只登记现场结果，不扣款、不保存卡号/PIN。
5. **异常及交班**：缺货、顾客未到等订单填写原因后取消；库存及场次名额在同一事务中释放一次。错码、重复交付、过期页面覆盖新库存均会被拒绝。工作人员、时间、订单状态、取消原因和收款登记写入持久化操作记录。

当天收款汇总只包含已登记的小票；旧版已完成但无小票的订单会单独提醒，不计入现金/卡/SNAP 汇总。不把现场记录当作银行结算、EBT 授权或核销对账。社区页面优先展示真实订单统计，2.5D 图收进可展开的规划示意图。

场次目前每市场每天一场，不支持跨午夜。商品按固定销售单位预购；需要现场称重改变金额、部分缺货、替换商品或已收款退款时，应先按现场流程协调，不能用取消已完成订单伪造退款。系统不自动发送备货确认或取货提醒，顾客在订单页查看状态。

### 建立独立运营数据库

使用新的数据库路径，保留已有演示库。以下命令在交互式终端执行，密码隐藏输入，至少 12 字符：

```bash
DATABASE_PATH=./data/operations.sqlite npm run setup:admin
DEMO_MODE=false DATABASE_PATH=./data/operations.sqlite HOST=127.0.0.1 PORT=3199 npm start
```

初始化不生成市场、商品或订单；若库含公开演示账号或已有管理员则拒绝覆盖。首位管理员登录后先建市场、登记商户、代录商品和开放场次，顾客才可预购。服务启动必须继续使用 `DEMO_MODE=false` 和相同数据库路径。生产环境另外需要持久化磁盘、HTTPS、备份与账号恢复机制；此命令只解决首次管理员建档。

升级现有运营库前先停服务，并备份 SQLite 主文件及仍存在的 `-wal` / `-shm` 旁文件；不要边运行边只拷贝主文件。再次启动会自动补充运营表、取货码及历史兼容字段，保留现有账号和订单。

### 验证

```bash
npm run check
```

包含 TypeScript 检查、前端构建、开市日程边界与日历导出测试，以及 API 集成测试。测试使用独立临时数据库，覆盖权限、订单履约、库存扣减与归还、越权操作、商品编辑、价格预测和持久化。

浏览器交互回归测试使用 Playwright 和独立临时数据库，不修改开发数据库：

```bash
npx playwright install chromium
npm run test:ui
```

如环境已安装 Chromium，可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:ui`。
测试覆盖开市日期、例外休市、营业季、导航出行方式、地址复制、日历下载、中英文与 320 / 390 / 768 / 1440 px 布局，以及登录后继续预购、取消登录后返回购物袋、提交等待与失败重试、库存变化和弹窗键盘操作；每个用例使用独立临时数据库与随机本机端口。

学校管理与 SNAP 测试还覆盖资格和接受核实、混合付款预估、历史快照、政策变更后的库存一致性、逐市场商户参与、三种角色隔离、旧数据库迁移、多市场与多商户统计去重、暂停预购时的库存一致性、市场设置持久化、管理数据失败重试及 320 / 390 px 手机导航。测试不修改开发数据库。

购物袋的商品数量、自提时段和备注通过 `sessionStorage` 保存在本标签页，同日刷新后可继续；不保存商品价格或库存。跨日、预购成功、退出登录、切换账号或刷新后无法确认原顾客身份时清空。存储被禁用时仍可正常操作，但不保留刷新前的草稿。顾客登录后仍需确认预购，不会自动创建订单。提交请求时会锁定表单和弹窗关闭操作，失败后恢复操作并保留输入。

顾客登录继续结账时保留原浏览位置；购物袋提供「继续选购」，从订单等其他页面直接回到商品区并定位键盘焦点。在购物袋内移除可购商品或减到零后，可撤销最近一次移除；按最新库存恢复，已下架或售罄商品不恢复，关闭购物袋后结束撤销。商品详情读取最新列表信息，库存、价格或下架变化会同步显示。商品卡与购物袋的连续加减使用最新数量，并遵守库存及服务端每种商品 100 份的上限；重复提交由前端锁定，避免同一轮操作创建多笔订单。

预购提交遇到库存冲突时读取最新商品，保留草稿并提示修正；会话过期时重新登录同一顾客后继续确认，换账号则清空上一位顾客的购物袋。订单页为各状态说明下一步，空筛选可返回全部订单；取消失败在确认弹窗内提供重试，订单已被商户更新时刷新状态。以上异常与连续点击流程都有浏览器回归覆盖。

构建后可由单个进程提供静态页面与 API：

```bash
npm run build
npm start
```

这会启动单个提供页面和 API 的 Node 服务，不等于发布公网网站。对外部署需要支持 Node.js 24 和持久化磁盘的托管环境；将 `DATABASE_PATH` 指向持久化目录，构建命令使用 `npm ci && npm run build`，启动命令使用 `npm start`。HTTPS 部署时按下方配置设置 `COOKIE_SECURE=true`。公开导览使用 GitHub Pages；完整应用的部署配置和持久化要求见 `docs/deployment.md`。

## 结构

```text
src/                  React + TypeScript 界面
server/app.mjs        Express HTTP API、会话与输入校验
server/services.mjs   预购、库存事务和订单状态流转
server/operations.mjs 学校代办、实际场次、取货与收款记录
server/provision.mjs  非演示环境首位管理员初始化
server/db.mjs         SQLite 表结构与演示数据
server/forecast.mjs   基于实际日期的线性回归与滚动回测
server/admin.mjs      学校管理 API、运营市场配置和全盘统计
src/SchoolAdmin.tsx   学校概览、市场设置、商户总览和社区影响
tests/                API 集成测试
```

业务逻辑层负责服务端定价、库存事务和订单状态校验，前端不直接访问数据库。金额统一存为整数美分；业务日期统一为 `America/New_York`。

## 主要接口

| `GET /api/config`、`GET /api/health`         | 运行配置与健康状态       | 公开              |

| `GET /api/auth/me`                           | 当前账号                 | 公开，可返回 null |
| `GET /api/orders`                            | 本人或所属商户订单       | 登录              |
| `POST /api/orders`                           | 按服务端价格预购、扣库存 | 顾客              |
| `PATCH /api/orders/:id/status`               | 取消、确认、完成         | 所属顾客 / 商户   |

| `PUT /api/admin/markets/:id/vendors` | 分配参与商户 | 学校管理方 |
| `GET /api/retailer/markets` | 查看所属运营市场 | 商户 |
| `PUT /api/admin/markets/:id/snap` | 市场 SNAP/EBT 接受、模式与核实记录 | 学校管理方 |
| `PUT /api/admin/markets/:id/vendors/:vendorId/snap` | 逐市场核实商户参与 | 学校管理方 |
| `POST /api/checkout/quote` | 服务端定价与 SNAP 逐项资格拆分 | 公开 |
| `GET /api/checkout/options?marketId=&date=` | 实际场次的可用自提时段与容量 | 公开 |

## 配置与雏形边界

见 `.env.example`。`npm run dev` / `npm start` 通过 Node 内置加载器读取 `.env`；显式导出的环境变量优先。

- `DATABASE_PATH`：SQLite 路径，默认 `./data/market.sqlite`。
- `PORT` / `HOST`：API 默认 `3001` / `0.0.0.0`；开发前端代理目前指向 `3001`。
- `DEMO_MODE`：开发环境默认开启，生产环境默认关闭。公开演示需显式设为 `true`；生产启动拒绝使用含公开演示账号的数据库。
- `COOKIE_SECURE`：生产环境默认 `true`；本机 HTTP 测试可显式设为 `false`。HTTPS 部署必须开启。

演示商品只在首次初始化时绑定当日日期，跨日不会自动重新上架。可在商户端把售卖日期更新为当天；历史记录随商户调价写入，不会自动伪造后续交易。

预测用最近最多 28 条历史记录按日期做线性回归，至少需要 7 条记录。误差来自最后最多 7 个时点的滚动单步回测；估计区间来自残差，不是价格保证，不考虑天气或供需。首版每笔订单限定同一市场、同一商户；称重商品最终金额需线下确认。演示模式中未配置排期的市场保留固定时段；一旦建立场次，该市场只按已开放的排期接单。非演示模式始终要求实际场次、截止时间及容量校验。

后续可以按反馈分步完善商品图片、多商户拆单、退款/部分履约和更完整的账号体系。正式上线前还需要独立处理账号恢复、商户准入、部署监控与支付等需求。

### 扩展学校统计看板

`/admin` 提供八项核心指标及四个分区：

- **数据总览**：完成交易额、预购数、去重顾客、平均完成订单金额、完成率、取消率、待履约金额、成交商户；预购/完成、金额、SNAP 意向趋势支持日/周/月汇总；自提星期与时段热力图、新参与与回访频次、待处理订单。
- **市场与商户**：同日期范围的全部市场比较，可按金额、预购、顾客排序并切换市场范围；商户成交排名。
- **商品与库存**：成交快照排行，按成交金额或完成订单数排序；各自单位的售出数量；今日上架、可购、低库存、售罄、分类结构和食品资格待核实提醒。
- **SNAP 与服务**：当前市场及商户接受准备情况；非取消的现场付款意向占比、提交时合资格食品预估、混合购物袋其他方式预估和去重意向顾客。

周期支持 7/30/90 天、全部时间及最多 366 天的自定义日期，`range=custom&from=YYYY-MM-DD&to=YYYY-MM-DD` 与 `market=id` 可分享/刷新。上期为紧邻本期之前的等长日期范围；上期为零时不制造百分比增幅，全部时间不比较上期。新参与与回访按所选市场范围内的完成订单历史判断，不代表留存率。统计使用当前订单状态；历史周期结果会随订单完成或取消而更新。库存和接受状态是当前快照。

可导出核心指标、每日趋势、全部市场对比、当前范围商户、全部商品排行、自提时段和付款意向 CSV。报表包含日期、范围、生成时刻和统计口径，不含顾客邮箱、姓名或备注；文本字段转义 CSV 和公式前缀。

为了评审有数据的图表，可运行 `node scripts/seed-analytics-preview.mjs`，生成独立的 `data/school-analytics-preview.sqlite`（96 天的合成订单、48 位样本顾客、4 个市场和示例付款意向）。使用 `DATABASE_PATH=./data/school-analytics-preview.sqlite PORT=3199 npm start` 查看。该库在学校页面与 CSV 中明确标记**合成演示样本**，不代表真实交易、实际顾客或 SNAP 授权/核销；不修改 `data/market.sqlite` 或原有 `school-admin-preview.sqlite`。

### 全站中英文覆盖

公共英文词典 `src/translations/common.ts` 与学校、市场日历、精简访客界面及演示数据词典合并后统一使用。新增文案使用 `t()`；动态通知与 API 错误保留完整句子及参数。英文模式下已收录的示例商品、市场和商户名称也会翻译，包含编辑表单；未编辑时保存保留原始数据。真实姓名、顾客备注与未知的自定义内容保留原文。

`tests/translations.test.mjs` 检查界面、参考资料及全部 API 服务的词典覆盖与参数；`tests/ui/english-coverage.spec.ts` 扫描顾客、商户及学校管理页面的正文、无障碍标签、输入框及弹窗，同时检查看板标签页、演示市场、动态错误和 320/390px 布局。
